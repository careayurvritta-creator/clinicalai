# Patient Documents System — Design Spec

**Date:** 2026-05-28
**Status:** Approved
**Replaces:** Case Collector module (`/?module=intake`)

---

## Overview

Replace the Case Collector module with a **Patient Documents** system — a folder-based document management interface for organizing clinical documents by patient. Each patient gets a unique clinical ID (AAH001, AAH002, ...) and pre-built document category folders. Files are stored in Supabase Storage with metadata tracked in PostgreSQL.

The existing 30-step intake wizard remains but moves exclusively to the Treatment Protocol module.

---

## Patient ID System

### Current State
- `patients` table has auto-generated `patient_code` in format `PT000001`
- Generated by `generate_patient_code()` database function

### New Design
- Add `clinical_id` column to `patients` table: format `AAH001`, `AAH002`, etc.
- New database sequence `clinical_id_seq` starting at 1
- New function `generate_clinical_id()` returns `AAH` + zero-padded sequence number
- Trigger on `patients` insert auto-generates `clinical_id` if not provided
- `clinical_id` is the primary display identifier in Patient Documents UI
- Existing `patient_code` (PT000001) remains for backward compatibility

## Document Categories

Pre-built folder categories per patient:

| Category | Slug | Description |
|---|---|---|
| Investigation Reports | `investigation-reports` | Blood tests, imaging, biopsy, lab reports |
| OPD Consultation Sheets | `opd-consultation-sheets` | Date-wise OPD visit records |
| IPD Sheets | `ipd-sheets` | Admission/discharge records, date-wise |
| OPD Registers | `opd-registers` | OPD register entries |
| IPD Registers | `ipd-registers` | IPD register entries |
| Panchakarma Therapy Notes | `panchakarma-notes` | Panchakarma therapy session records |
| Reimbursement Forms | `reimbursement-forms` | CGHS/insurance claim forms |
| Medical Certificates | `medical-certificates` | Fitness certificates, referral letters |
| Prescriptions | `prescriptions` | Prescribed medications |
| Discharge Summaries | `discharge-summaries` | Hospital discharge documents |

Categories are hardcoded constants in `src/lib/constants.ts`. Folders are virtual — created on first file upload. No separate folders table needed.

## Storage Architecture

### Supabase Storage Bucket
- Bucket name: `patient-documents`
- Public: false (signed URLs for access)
- File size limit: 50MB per file
- Allowed MIME types: `application/pdf`, `image/jpeg`, `image/png`, `image/webp`, `application/vnd.ms-excel`, `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`, `text/csv`

### Path Convention
```
{clinical_id}_{PatientNameSanitized}/{category-slug}/{date}_{originalFilename}
```

Example:
```
AAH001_Vijaydutt_Sharma/investigation-reports/2026-01-15_CBC_Report.pdf
AAH001_Vijaydutt_Sharma/reimbursement-forms/2026-05-28_Reimbursement_Claim.pdf
AAH002_Ramesh_Kumar/opd-consultation-sheets/2026-03-10_OPD_Sheet.pdf
```

## Database Schema

### Migration: `014_patient_documents.sql`

```sql
-- Add clinical_id to patients
ALTER TABLE patients ADD COLUMN clinical_id TEXT UNIQUE;

CREATE SEQUENCE clinical_id_seq START 1;

CREATE OR REPLACE FUNCTION generate_clinical_id()
RETURNS TRIGGER AS $$
BEGIN
  IF NEW.clinical_id IS NULL THEN
    NEW.clinical_id := 'AAH' || LPAD(nextval('clinical_id_seq')::TEXT, 3, '0');
  END IF;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER set_clinical_id
  BEFORE INSERT ON patients
  FOR EACH ROW
  EXECUTE FUNCTION generate_clinical_id();

-- Backfill existing patients (wrap ROW_NUMBER in CTE for correct UPDATE)
WITH numbered AS (
  SELECT id, 'AAH' || LPAD((ROW_NUMBER() OVER (ORDER BY created_at))::TEXT, 3, '0') AS new_clinical_id
  FROM patients WHERE clinical_id IS NULL
)
UPDATE patients SET clinical_id = numbered.new_clinical_id
FROM numbered WHERE patients.id = numbered.id;

-- Patient documents table
CREATE TABLE patient_documents (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  patient_id UUID NOT NULL REFERENCES patients(id) ON DELETE CASCADE,
  category TEXT NOT NULL,
  filename TEXT NOT NULL,
  storage_path TEXT NOT NULL,
  file_size BIGINT NOT NULL,
  file_type TEXT NOT NULL,
  upload_date TIMESTAMPTZ NOT NULL DEFAULT now(),
  tags TEXT[] DEFAULT '{}',
  notes TEXT,
  uploaded_by UUID REFERENCES profiles(id),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_patient_documents_patient ON patient_documents(patient_id);
CREATE INDEX idx_patient_documents_category ON patient_documents(category);
CREATE INDEX idx_patient_documents_date ON patient_documents(upload_date);

-- Full-text search on filenames and notes
ALTER TABLE patient_documents ADD COLUMN search_vector tsvector
  GENERATED ALWAYS AS (
    to_tsvector('english', coalesce(filename, '') || ' ' || coalesce(notes, ''))
  ) STORED;

CREATE INDEX idx_patient_documents_search ON patient_documents USING gin(search_vector);

-- RLS
ALTER TABLE patient_documents ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can manage their own patient documents"
  ON patient_documents FOR ALL
  USING (uploaded_by = auth.uid());

-- Auto-update updated_at
CREATE OR REPLACE FUNCTION update_patient_documents_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER set_patient_documents_updated_at
  BEFORE UPDATE ON patient_documents
  FOR EACH ROW
  EXECUTE FUNCTION update_patient_documents_updated_at();
```

## UI Design

### Module Rename
- Sidebar: "Case Collector" → "Patient Documents" (clipboard-list icon)
- Mobile nav: "Intake" → "Documents"
- Header title: "Case Collector" → "Patient Documents"
- URL: `/?module=documents` (new key, `intake` → `documents`)

### Page Layout (Patient Documents Module)

**State 1: Patient Selection**
- Search bar: search by name, phone, or clinical ID (AAH001)
- Recent patients grid (last 10 accessed)
- Patient card shows: clinical_id, name, age, gender, last upload date

**State 2: Patient Folder View**
- Patient header: clinical_id, name, age, gender, phone
- Grid of 10 category folder cards
- Each folder card: icon, category name, file count, last upload date
- Quick upload button per folder
- "Back to patients" navigation

**State 3: Folder Contents**
- Breadcrumb: Patients > AAH001 {Name} > Investigation Reports
- File list (table view): filename, date, size, type icon, actions (preview, download, delete)
- Sort by: date (newest/oldest), name (A-Z/Z-A), size
- Filter by: date range, file type
- Upload zone: drag-drop area at top or dedicated button
- Bulk select + delete

**Upload Modal (Single File)**
- File picker or drag-drop
- Preview (for images/PDFs)
- Metadata form: upload date (default today), tags (comma-separated), notes
- Category pre-selected if uploading from within a folder

**Bulk Upload**
- Drag-drop multiple files
- Auto-categorize based on filename patterns (optional)
- Category selector for all files
- Progress bar per file

### Preview
- PDF: In-browser viewer using existing `/api/pdf` extraction
- Images: Inline preview with zoom
- Excel/CSV: Download only (no inline preview)

## API Routes

### `POST /api/patient-documents`
Upload a document.
```typescript
// Request: multipart/form-data
{
  patient_id: string;
  category: string;
  file: File;
  tags?: string;
  notes?: string;
}

// Response
{ document: PatientDocument }
```

### `GET /api/patient-documents?patient_id={id}&category={slug}`
List documents for a patient, optionally filtered by category.
```typescript
// Response
{ documents: PatientDocument[], counts: Record<string, number> }
```

### `GET /api/patient-documents/[id]`
Get single document with signed download URL.

### `DELETE /api/patient-documents/[id]`
Delete document (removes from storage + DB).

### `GET /api/patients/search?q={query}`
Search patients by name, phone, or clinical_id for the patient selector.

## Migration Path

1. **Database migration** (014): Add clinical_id, patient_documents table, backfill existing patients
2. **Storage bucket**: Create `patient-documents` bucket in Supabase Dashboard
3. **Rename module**: Update all references from "Case Collector"/"intake" to "Patient Documents"/"documents"
4. **Move intake wizard**: In `ChatPanel.tsx`, change the condition so `CaseCollectorChat` renders when `activeModule === 'treatment-protocol'` (not `intake`). The wizard file itself (`CaseCollectorChat.tsx`) stays unchanged — only the conditional rendering in `ChatPanel.tsx` changes. The `intake` module key is removed from the store; `documents` replaces it.
5. **Build Patient Documents UI**: New components for folder-based document management
6. **API routes**: New patient-documents endpoints

## Out of Scope

- AI analysis of uploaded documents (future feature — the `attachments` table already has `ai_analysis` column)
- OCR text extraction from scanned documents
- Document versioning
- Multi-user collaboration on documents
- Document sharing/permissions beyond basic RLS
